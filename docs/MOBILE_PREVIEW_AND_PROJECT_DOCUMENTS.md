# Bellomassi — Mobile App Preview and Project Documents

Two tools in the office app under **Project Workspace**. No business data, storage keys or data version changed
(data version stays 8). Three permission keys were added to the catalog (catalog version 3); `rbacService.syncCatalog`
grants them to the system roles on start-up without touching custom roles or earlier administrator edits.

| Permission | Default roles (+ Super Admin) | Gates |
|---|---|---|
| `mobile.preview` | Administrator, Sales Manager, Dispatcher | Mobile App Preview |
| `project.documents.view` | Administrator, Sales Manager, Dispatcher, Finance | Project Documents (shareable + internal documents) |
| `project.documents.restricted` | Administrator | Restricted documents (Security, Infrastructure, Risk & Change) |

## 1. Mobile App Preview — `/mobile-preview`

A phone emulator that runs the **real** application. The device screen is a same-origin `<iframe name="bm-device-preview">`
loading the normal routes (`/driver/*`, `/customer/*`, `/notifications`), so the driver and customer layouts, services,
validation and LocalStorage data are the real ones and the app's responsive CSS reacts to the phone width.

| Feature | Detail |
|---|---|
| Device frames | Android (punch-hole camera) and iPhone-style (island); rounded body, side buttons, shadow, clipped screen, status bar (live time, signal, Wi-Fi, battery), gesture / home indicator |
| Sizes | Small 360 × 640 · Standard 375 × 812 · Modern 390 × 844 · Large 430 × 932 |
| Toolbar | Driver / Customer switch, Android / iPhone, size, portrait / landscape, zoom − / + / Fit, back, reload, fullscreen, exit |
| Side panel | Current screen and signed-in device user, "Sign in as demo driver / customer", sign out, quick links to every required screen |
| Session | Inside the frame the session is stored under `bellomassi_preview_session`, so signing in as a driver or customer never signs the office user out. Business data is shared: a delivery confirmed in the device appears in the office screens. |
| Bridge | `components/mobilePreview/PreviewBridge.jsx` (inside the app) reports the screen to the emulator and performs its navigate / back / sign-in / sign-out requests through the app's own router and auth service; messages are accepted from the same-origin parent only. |
| Responsive | Desktop: device centred, toolbar + side panel. Tablet: smaller device. Phone: device fits the viewport, size / platform / zoom controls hidden, fullscreen available. |

Navigation changes in the real apps (requested for the device experience):
- Driver bottom bar: **Home · Deliveries · Route · History · Profile** (Route kept so the route map stays one tap away).
- Customer bottom bar: **Home · Products · Orders · Tracking · Profile**; the cart moved to a header button with an item
  badge; new **Tracking** page `/customer/tracking` lists the customer's own deliveries on the way and recently delivered.

Limits: it is a browser preview, not a native app — GPS is DEMO GPS, camera / signature use the browser, and there are
no push notifications, background location or offline mode. Toasts appear at the top of the device and can briefly
cover the header icons, as on the real web app.

## 2. Project Documents — `/project-documents`

A library of the real documentation package in `docs/BELLOMASSI_PROJECT_DOCUMENTATION`.

| Part | Detail |
|---|---|
| Catalogue | `src/data/projectDocuments.js`, generated by `scripts/build-project-documents.mjs` (`npm run docs:catalog`, also run before every build) from the package's official index `BELLOMASSI_DOCUMENTATION_INDEX.xlsx`. 544 files: 204 Markdown, 204 Word, 36 PDF, 29 Excel, 1 PowerPoint, 1 OpenAPI YAML, 23 Mermaid sources, 23 SVG + 23 PNG diagrams. Each entry: id, title, fileName, filePath, category, fileType, description, version, updatedAt, status, size, available, previewSupported, access, assets. |
| File serving | `vite-plugins/projectDocuments.js`: dev server and `vite preview` stream only catalogue-listed files (and the screenshots their Markdown references) from the docs folder; anything else under `/project-documents/` is a 404. `vite build` copies exactly those files to `dist/project-documents/` (about 132 MB). No document is stored in LocalStorage. |
| Open / preview | PDF in the browser's PDF viewer; Markdown rendered (marked + DOMPurify, images resolved, Mermaid shown as source); Word converted in the browser (mammoth); Excel cell values per sheet (first 300 rows); SVG / PNG images; Mermaid / YAML as text; PowerPoint: no preview, download only. |
| Downloads | Each file downloads as the actual file (fetched, checked not to be an HTML fallback or empty). Multi-select (row, visible, all available, clear, count) → one file directly or `Bellomassi_Selected_Documents.zip`. Category ZIP per category. **Download all** → `Bellomassi_Project_Documents.zip` with category folders, the screenshots used by Markdown files, and `_manifest.txt` listing included and excluded files. Duplicate names inside a ZIP get " (2)". |
| Missing files | Files listed in the index but absent are catalogued as unavailable; on page load every file is re-checked with a HEAD request. Unavailable files show the reason, cannot be opened or downloaded, are excluded from ZIPs and listed in the ZIP summary. |
| Filters | Search (title, file name, document ID), category, file type, status (available / unavailable / restricted / shareable), sort by name, updated date, file type, size, category, ascending / descending. |
| Audit | Every download and ZIP export is written to the audit log (module "Project workspace", action Export). |

Prototype security limitation: the screens and every action check permissions, but the files are static files, so their
URLs are not protected by the demo sign-in. Production: Django REST API + PostgreSQL document metadata + private
Cloudflare R2 / S3 storage with short-lived signed download URLs, served only after a server-side permission check.
