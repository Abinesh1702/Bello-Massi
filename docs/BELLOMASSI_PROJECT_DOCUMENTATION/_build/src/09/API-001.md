## 1. What exists today

| Layer | Status | Description |
|---|---|---|
| Frontend functionality | VERIFIED | 84 browser service modules implement every workflow (e.g. `orderService.submitOrder`, `approvalService.approveOrder`, `deliveryService.confirmDelivery`). |
| Mock API behaviour | PROTOTYPE | Services return `{ ok, record, error, errors }` synchronously from LocalStorage; simulated providers for GPS, OTP, email, WhatsApp, OCR, AI. |
| Integration gateway contract | NOT VERIFIED | Optional HTTP contract (`VITE_INTEGRATION_GATEWAY_URL`) for email, OpenWA, OCR, AI and ML; no gateway is deployed. |
| REST API | PROPOSED | This specification — 140 endpoints in 15 domains ({{ref:BM-API-002}}). |
| Production integrations | PROPOSED | Maps / Routes, SMS / WhatsApp, email, OCR, SAP ({{ref:BM-API-019}}). |

## 2. Conventions

| Topic | Convention |
|---|---|
| Base URL | `https://<host>/api/v1` (versioned in the path; breaking changes → v2) |
| Format | JSON (UTF-8); `multipart/form-data` for files; ISO-8601 dates; times UTC with offset; money as decimal strings |
| Authentication | `Authorization: Bearer <JWT access token>` (15 min); refresh token rotation; MFA for privileged roles |
| Authorisation | Permission key per endpoint (same 110 keys as the prototype) + object-level data scope |
| Pagination | `?page=1&page_size=25` → `{count, next, previous, results[]}` (max page size 200) |
| Filtering / sorting | Query parameters (`status`, `from`, `to`, `search`, `ordering=-created_at`) |
| Idempotency | `Idempotency-Key` header required on submit, approve, confirm, complete, write-off; repeated keys return the first result |
| Concurrency | `version` field (optimistic locking) on orders, dispatches, stock; `409 Conflict` on mismatch |
| Errors | `{ "code": "ORDER_NOT_EDITABLE", "message": "…", "errors": { "field": "message" } }` |
| Status codes | 200 / 201 / 202 / 204; 400 validation; 401 unauthenticated; 403 forbidden; 404 not found or out of scope; 409 state conflict; 413 / 415 file; 422 business rule; 429 rate limit; 503 provider unavailable |
| Rate limiting | Per user and per IP; stricter on auth, OTP and password endpoints |
| Real-time | WebSocket `wss://<host>/ws/` channels: `tracking.dispatch.<id>`, `tracking.order.<id>` (customer, own order only), `monitor.orders`, `notifications.user.<id>` |
| Webhooks | Provider callbacks signed (HMAC) and verified; replay-protected |
| Documentation | OpenAPI 3.0 generated by drf-spectacular; draft file BM-API-018 |

## 3. Error message reuse

The prototype's user messages (e.g. "Only draft orders can be deleted. Submitted orders are kept for the audit trail.")
are the reference texts; each business rule in {{ref:BM-SYS-007}} becomes an error `code`.
